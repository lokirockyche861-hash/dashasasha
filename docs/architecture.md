# Архитектура проекта

Данный документ описывает общую архитектуру фронтенда, бэкенда и ключевые требования к реализации новых фич.

---

## 1. Архитектура фронтенда

Фронтенд построен на **Nuxt 4 (Vue 3)** и использует систему рендеринга на основе JSON-конфигурации (**Data-Driven UI**).

### Роутинг и страница урока
Вся логика отображения уроков сосредоточена в файле `pages/lesson/[id].vue`:
- **Динамический роут:** При открытии URL вида `/lesson/lesson1` Nuxt передает `lesson1` в качестве параметра `id`.
- **Загрузка данных:** Функция `loadLesson(id)` обращается к реестру `lessons/index.js`, который служит манифестом всех доступных уроков.
- **Ленивая загрузка (Lazy Loading):** Данные уроков (`.json`-файлы) подгружаются динамически (`dynamic import`) только по мере необходимости.

### Рендеринг контента (`SimpleRenderer`)
Для теоретических уроков используется компонент `SimpleRenderer.vue`:
- **Принцип:** Получает массив блоков из JSON-файла урока (поле `content`).
- **Диспетчеризация:** В цикле `v-for` вызывает метод `getComponent(node)`.
- **Маппинг:** Значение `type` из JSON (например, `"QuizCheckbox"`, `"Table"`, `"markdown"`) преобразуется в соответствующий Vue-компонент (`QuizCheckbox.vue`, `Table.vue`, `Markdown.vue`).

### Структура контента уроков
- Каждый урок — это массив JSON-узлов с полями `id`, `type`, `content` и метаданными проверки.
- Подробная спецификация форматов описана в [docs/lesson-schema.md](lesson-schema.md).

### Деревья решений и практические уроки (Decision Tree)
В `pages/lesson/[id].vue` реализована проверка `isDecisionTree`:
- Если урок является практическим алгоритмом (например, `lesson-pol`, `lesson-sh-ts-mid`, `lesson-soft-hard`), подключается лейаут `GraphLayout` и контейнер [`PracticeLessonContainer.vue`](../components/decision-tree/PracticeLessonContainer.vue) (двухпанельный макет: сворачиваемая вводная теория слева + тренажер с интерактивным графом справа).
- Практические уроки хранятся автономно в `lessons/practice/lesson-<name>.json` (пакет `theory`, `rule` и `tasks`).
- Сервер валидирует шаги через динамический реестр [`server/utils/graphRegistry.ts`](../server/utils/graphRegistry.ts).
- Подробная спецификация графов и макетов описана в [docs/decision-tree.md](decision-tree.md).

### Добавление новых типов заданий
Благодаря компонентной архитектуре добавление новой механики требует:
1. Создания Vue-компонента в `/components`.
2. Регистрации типа в `SimpleRenderer.vue`.
3. Описания JSON-структуры узла с поддержкой пропса `savedState` для восстановления ответов.

## 2. Архитектура бэкенда

Бэкенд интегрирован в Nuxt на базе серверного движка **Nitro** (`/server`).

### Серверный движок (Nitro)
- Файлы в папке `server/api` автоматически регистрируются как API-эндпоинты.
- Например, `server/api/attempts.post.ts` обрабатывает запросы по маршруту `POST /api/attempts`.

### База данных (PostgreSQL + Drizzle ORM)
- **PostgreSQL:** Основное хранилище (локально или через Supabase).
- **Drizzle ORM:** Схема описана в `server/db/schema.ts`, конфигурация миграций — в `drizzle.config.ts`.
- Взаимодействие с базой изолировано через репозитории (например, `attemptRepo`).

### Жизненный цикл обработки запроса попытки (`/api/attempts`)
При отправке ответа пользователем:
1. **Аутентификация:** Проверка cookie `uid` (идентификатор пользователя). При отсутствии возвращается HTTP 401.
2. **Валидация:** Проверка обязательных полей (`taskId`, `answerType` и т.д.). Для графовых заданий запускается логика валидации переходов `validateGraphNode`.
3. **Серверная проверка ответа:** Сервер самостоятельно определяет правильность (`isCorrect`) и рассчитывает балл (`score`), предотвращая фальсификацию на клиенте.
4. **Сохранение:** Данные сохраняются через репозиторий `attemptRepo.create` в таблицу `attempts`.

## 3. Ключевые требования к разработке фич

1. **Idempotency (Идемпотентность):** Перезагрузка страницы не должна приводить к потере прогресса.
2. **Partial State (Восстановление ошибок):** Если задание решено неверно или частично, сохраненное состояние всё равно восстанавливается, и пользователю показывается результат с подсветкой ошибок (`showResults = true`).
3. **Immutability (Неизменяемость лога):** Записи в таблице `attempts` не редактируются и не удаляются при повторных ответах. Каждая проверка создаёт новую запись в истории.
