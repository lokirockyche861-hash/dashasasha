# Архитектура практических уроков и деревьев решений (Decision Tree / Graph)

Практические уроки русского языка моделируются в виде алгоритмических тренажеров — графов принятия решений и процедурных чеклистов. Ученик проходит по веткам алгоритма, отвечая на вопросы-шаги, и вводит итоговое слово.

---

## 1. Архитектурная модель: Автономные пакеты уроков

Каждый практический урок представляет собой самодостаточный автономный JSON-пакет в директории `lessons/practice/`:
- `lessons/practice/lesson-pol.json` (Урок 14: Пол- и полу-)
- `lessons/practice/lesson-sh-ts-mid.json` (Урок 1: Ь после шипящих и Ц в середине слова)
- `lessons/practice/lesson-soft-hard.json` (Урок 2: Разделительные Ъ и Ь)
- `lessons/practice/lesson-o-yo-root.json` (Урок 4: О-Ё после шипящих в корне)
- `lessons/practice/lesson-prefix-z-s.json` (Урок 13: Правописание согласных на конце приставок З/С)
- `lessons/practice/lesson-vowels-after-ts.json` (Урок 5: Гласные после Ц)
- `lessons/practice/lesson-root-vowels-checked.json` (Урок 7: Безударные проверяемые гласные в корне)
- `lessons/practice/lesson-silent-consonants.json` (Урок 8: Непроизносимые согласные в корне слова)
- `lessons/practice/lesson-voiced-unvoiced.json` (Урок 9: Оглушение и озвончение согласных в корне)
- `lessons/practice/lesson-vowels-after-sibilants.json` (Урок 3: Гласные после шипящих)
- `lessons/practice/lesson-double-consonants.json` (Урок 10: Удвоение согласных на стыке морфем)
- `lessons/practice/lesson-prefix-vowels.json` (Урок 11: Безударные гласные в приставках)
- `lessons/practice/lesson-prefix-pre-pri.json` (Урок 12: Правописание приставок ПРЕ- и ПРИ-)

### Структура файла практического урока (`lessons/practice/lesson-<name>.json`):

```json
{
  "id": "lesson-soft-hard",
  "title": "Урок 2. Разделительные Ъ и Ь",
  "topicId": "phonetics",
  "lesson_version": "1.0",
  "theory": [
    /* 1. Вводная интерактивная теория: Markdown, QuizSelect, QuizCheckbox */
  ],
  "rule": {
    /* 2. Топология графа/алгоритма */
    "graphId": "graph_sep_signs_v1",
    "title": "Разделительные Ъ и Ь",
    "layout": "spine",
    "start_node": "q1",
    "ruleId": "rule_sep_signs",
    "topicId": "phonetics",
    "nodes": [ ... ]
  },
  "tasks": [
    /* 3. Тренировочная база заданий (слов) */
    {
      "id": "t1",
      "skill_id": "sep_prefix",
      "content": {
        "word": "с___едобный",
        "correct_path": [
          { "id": "q1", "option_id": "q1_op_yes" }
        ],
        "correct_answers": ["съедобный", "ъ"]
      }
    }
  ]
}
```

## 2. Пользовательский интерфейс (`PracticeLessonContainer.vue`)

Урок рендерится через двухпанельный адаптивный контейнер [`PracticeLessonContainer.vue`](../components/decision-tree/PracticeLessonContainer.vue):
1. **Левая панель («Изобретение правила»):** Вводная теория (лонгрид с интерактивными вопросами). По умолчанию открыта при первом входе, может сворачиваться в компактную кнопку-шпаргалку («Теория») и разворачиваться обратно в любой момент.
2. **Правая панель (Тренажер):** 
   - Поле ввода текущего тренировочного слова (`word-stage`);
   - Интерактивный граф принятия решений (`ActiveTree.vue`);
   - Список уже освоенных слов текущей сессии для фиксации материала.

## 3. Топология и флаги позиционирования (`SpineTreeLayout.vue`)

Для каскадных деревьев решений архетипа `SpineDecisionTree` используется специализированный макет [`SpineTreeLayout.vue`](../components/decision-tree/layouts/SpineTreeLayout.vue).

### Флаги направлений (`direction`):
Каждый вариант ответа (`option.direction`) или терминальный узел (`result.direction`) может явно задавать направление ветвления:

| Значение `direction` | Расположение карточки | Тип соединительной стрелки |
| :--- | :--- | :--- |
| `"left"` | В левой боковой колонке (`side-cell left`) напротив вопроса | Горизонтальная стрелка налево |
| `"right"` | В правой боковой колонке (`side-cell right`) напротив вопроса | Горизонтальная стрелка направо |
| `"left-under"` | В нижнем ряду под вопросом, слева (под кнопкой «Да») | Строго вертикальная стрелка вниз (90°) |
| `"right-under"` | В нижнем ряду под вопросом, справа (под кнопкой «Нет») | Строго вертикальная стрелка вниз (90°) |

### Правила верстки финальных карточек:
- Ширина контейнера `.bottom-results-row` строго синхронизирована с `.question-node` (`max-width: 400px; min-width: 250px`).
- Стрелки к `left-under` и `right-under` рассчитываются с `startX === endX` (абсолютно вертикальные линии без диагональных перекосов).
- Резервные плашки `Да` / `Нет` на карточках результатов опущены, так как карточка позиционируется строго под соответствующей кнопкой вопроса.

### Охват уроков архетипа `SpineDecisionTree`:
- **Урок 1 (`lesson-sh-ts-mid`):** Ь после шипящих и Ц в середине слова.
- **Урок 2 (`lesson-soft-hard`):** Разделительные Ъ и Ь.
- **Урок 11 (`lesson-prefix-vowels`):** Безударные гласные в приставках (линейный вертикальный каскад из 8 вопросов со сбросом влево особых приставок `пре/при`, `раз/роз`, `пери`, `пере`, `ультра/экстра`, `интро`, `интра`, беглого `О` и нижним терминалом `По слуху (сильная позиция)`).
- **Урок 12 (`lesson-prefix-pre-pri`):** Правописание приставок ПРЕ- и ПРИ- (двусторонний каскад: 4 значения приставки ПРИ- уходят влево `direction: "left"`, 2 значения приставки ПРЕ- уходят вправо `direction: "right"`, а словарные слова уходят в нижний терминал `direction: "right-under"`).
- **Урок 14 (`lesson-pol`):** Правописание пол- и полу-.

## 4. Архетип `BinaryDecisionTree` (`BinaryTreeLayout.vue`)

Для разветвлённых бинарных деревьев, каскадов и симметричных разветвлений используется [`BinaryTreeLayout.vue`](../components/decision-tree/layouts/BinaryTreeLayout.vue).

### Адаптивная конфигурация ярусов (`layoutTiers`):
Топология ярусов задаётся декларативно по `start_node`:
- **Симметричные деревья (Урок 4):** 3 яруса, корень делится на две симметричные ветки (левая ветка вопросов и правая ветка вопросов с парными исходами `results-pair`).
- **Каскады с тупиковыми выходами (Урок 13):** Ветка «Нет» уходит в тупиковый результат (например, `По слуху (сильная позиция)`), а ветка «Да» продолжается вглубь до выбора конечных букв (`З` / `С`).
- **Многоуровневые каскады (Урок 5):** 5 ярусов, каскадные вопросы с выходом в повторяющиеся терминалы (`Пишем Ы`) и параллельные ветви (`Пишем И`).

### Золотые стандарты UI/UX:
1. **Концепция «Капсула вердикта»:**
   - Карточки вопросов имеют чисто-белый фон (`#FFFFFF`), а карточки терминальных результатов — тонированный фон `#F8FAFC`, создавая четкую визуальную дифференциацию «где думать» и «где итог».
   - Карточки вердикта имеют компактную высоту `auto` (~50px) и вертикальное выравнивание `align-self: center`. Они не растягиваются под высоту громоздких вопросов.
   - Из карточек вердикта исключены длинные списки примеров (спойлеры к тренировочным словам) — формулируется только краткая формула правила (например, *В суффиксе -ын-*).
2. **Устранение эффекта «ложного столбика»:**
   - В каскадах, где терминальные ноды `Пишем Ы` выстраиваются друг под другом, за счёт компактной высоты вердикта образуется вертикальный разрыв (~75px), разрушающий ложное гештальт-восприятие единой колонки.
3. **Ортогональные стрелки SmoothStepEdge:**
   - Соединения входят строго под углом 90° в верхний центр карточки с радиусом скругления угла `R=10px`.
   - Неактивные стрелки: `2px #94A3B8`.
   - Активный доступный переход: `2px #6366F1`.
   - Пройденный верный шаг: `2.5px #10B981`.
   - Неактивные отсечённые ветви приглушаются до `opacity: 0.3` с помощью граф-агностического обхода `isReachable`.
4. **Семантика цветов:**
   - Нажатие на кнопку «Нет» при верном ответе подсвечивается спокойным изумрудным цветом (`#10B981`).
   - Красный цвет (`#EF4444` + анимация `shake`) используется исключительно для ошибочного выбора ученика.

## 5. Архетип `StepAlgorithm` (`StepAlgorithmLayout.vue`)

Для линейных процедурных правил без ветвления графа (проверка безударных корней, непроизносимых согласных, оглушения/озвончения) используется пошаговый чеклист [`StepAlgorithmLayout.vue`](../components/decision-tree/layouts/StepAlgorithmLayout.vue) при `rule.layout: "steps"`.

### Ключевые принципы реализации:
1. **Focus + Context (Прозрачный маршрут):**
   - Все шаги чеклиста (1–6) видны сразу: будущие шаги отображаются полупрозрачными (`opacity: 0.45`), пройденные сворачиваются в компактные плашки с изумрудной галочкой `✓`, а текущий шаг активен с акцентной подсветкой (`#6366F1`).
2. **Интерактивные чипсы подбора проверочного слова (Шаг 3):**
   - Вместо ввода с клавиатуры ученику предлагаются чипсы с вариантами слов (`task.content.check_options`), что исключает опечатки и позволяет дидактически отслеживать конкретные типы ошибок.
3. **Отработка правил и ловушек (Шаги 4–5):**
   - При выборе ошибочного слова-ловушки (например, глагола на *-ывать* или слова с неполногласием) чеклист показывает предупреждающую плашку правила (`.trap-warning-banner`) с понятным методическим объяснением и оставляет шаг активным для выбора правильного проверочного слова.
4. **Результат и разблокировка:**
   - После прохождения всех проверок финальный шаг (`type: "result"`) демонстрирует капсулу с найденной в сильной позиции буквой (или специальную капсулу `.is-zero-verdict` при отсутствии непроизносимой согласной) и генерирует событие `@completed`, разблокируя поле ввода слова в левой панели.
   - Ученик вводит в левое поле проверенное **слово целиком** (например, `звёздный`, `ужасный`, `глаз`, `лодка`).

### Охват уроков архетипа `StepAlgorithm`:
- **Урок 3 (`lesson-vowels-after-sibilants`):** 4 шага, гласные после шипящих (жи-ши, ча-ща, чу-щу, же-ше и иноязычные исключения жюри, брошюра, парашют).
- **Урок 7 (`lesson-root-vowels-checked`):** 6 шагов, проверка безударной гласной в корне (отсечение корней с чередованием, неполногласия и глаголов на -ывать/-ивать).
- **Урок 8 (`lesson-silent-consonants`):** 4 шага, проверка непроизносимых согласных в сильной позиции перед гласной, включая слова без согласного (`letter: "0"`).
- **Урок 9 (`lesson-voiced-unvoiced`):** 4 шага, проверка парных звонких/глухих согласных в сильной позиции (перед гласными, сонорными, [в]).
- **Урок 10 (`lesson-double-consonants`):** 4 шага, проверка удвоения согласных на стыке морфем (приставка+корень и корень+суффикс/постфикс).

## 6. Серверный реестр графов (`server/utils/graphRegistry.ts`)

Валидация попыток шагов в графе выполняется через эндпоинт `POST /api/attempts`.
Для проверки существования узлов и опций используется утилита `validateGraphNode(graphId, subTaskId, optionId)`:
- `graphRegistry` автоматически сканирует все файлы `lessons/practice/*.json` и `lessons/graph.json` при старте.
- Используется только нативный модуль `node:fs` (`readFileSync`, `readdirSync`, `existsSync`).  
  > [!IMPORTANT]
  > В серверном слое Nitro запрещено использовать Vite-макрос `import.meta.glob`, так как в dev-режиме Nuxt он вызывает фатальный сбой `globalThis._importMeta_.glob is not a function`.
- При поступлении запроса с неизвестным `graphId` реестр выполняет ленивую дозагрузку файлов с диска (`loadGraphs(true)`), позволяя добавлять новые уроки без перезапуска dev-сервера.

## 7. Двухэтапная аналитика попыток (Payload)

Действия ученика логируются в PostgreSQL (таблица `attempts`) двумя отдельными записями:

### 1. Шаг внутри дерева (`ActiveTree.vue`)
При клике на опцию внутри узла отправляется попытка шага:
- `taskType`: `"DecisionTree"`
- `answerType`: `"select"`
- `taskId`: ID задания (`t1`, `t2`...).
- `subTaskId`: ID текущего вопроса (`q1`, `q2`...).
- `selectedOptionId`: ID выбранного варианта (`q1_op_yes`, `q1_op_no`).
- `userAnswerIsCorrect`: `true`, если шаг совпадает со значением в `correct_path` для данного шага.
- `graphId`, `topicId`, `ruleId`, `skillId`: контекст правила.

### 2. Ввод и проверка финального слова
Когда ученик доходит до узла с результатом и отправляет слово в инпуте:
- `taskType`: `"DecisionTreeInput"`
- `answerType`: `"input"`
- `taskId`: ID задания (`t1`, `t2`...).
- `subTaskId`: ID инпута (например, `"t1_input"`).
- `answerText`: Текст, введенный учеником.
- `userAnswerIsCorrect`: `true`, если введенный текст содержится в массиве `correct_answers`.
- `responseMs`: Время решения задания (в миллисекундах) с момента его активации.
