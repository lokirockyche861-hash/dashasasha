# Архитектура хранения данных и API прогресса

Документ описывает структуру базы данных, логику сохранения попыток пользователей и механизм восстановления прогресса в интерфейсе.

---

## 1. База Данных (PostgreSQL + Drizzle ORM)

Основная таблица для хранения прогресса — `attempts`. В ней сохраняется **каждая попытка** ответа пользователя на конкретное задание или подзадачу.

### Схема таблицы `attempts`

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `attemptId` | `uuid` | Первичный ключ (PK), генерируется автоматически |
| `userId` | `text` | ID пользователя (из cookie `uid`) |
| `sessionId` | `uuid` | ID сессии (из cookie `sid`) |
| `lessonId` | `text` | ID урока (например, `lesson1`) |
| `taskId` | `text` | ID компонента-задания (например, `l1-n4-qchk-o2pn`) |
| `subTaskId` | `text` | ID подзадачи (для составных заданий, nullable) |
| `taskType` | `text` | Тип задания (`QuizSelect`, `FillInTheBlank` и т.д.) |
| `answerType` | `text` | Тип ответа (`select`, `input`, `match`, `multi-select`) |
| `isCorrect` | `boolean` | Верно ли решено задание |
| `answerText` | `text` | Текстовый ответ пользователя (для `input`-задач) |
| `selectedOptionId` | `text` | ID выбранной опции (для `select`-задач) |
| `selectedOptionIds` | `jsonb` | Массив ID (для `multi-select` или `drag-and-drop`) |
| `createdAt` | `timestamp` | Время фиксации попытки |

> [!IMPORTANT]
> **Принцип расчета текущего прогресса:**
> Прогресс строится на основе **самой последней** попытки (`ORDER BY createdAt DESC LIMIT 1`) для каждой уникальной пары `taskId` + `subTaskId`.

---

## 2. API и Сохранение Прогресса

### Сохранение данных (Frontend -> Backend)
Отправка результатов осуществляется через сервис `AnalyticsService.logAttempt(payload)`:
- **Эндпоинт:** `POST /api/attempts`
- **Поведение:** Каждое действие проверки (клик по кнопке «Проверить») отправляет новую запись в таблицу `attempts`. Старые записи не перезаписываются — ведется полный исторический аудит-лог.

### Восстановление прогресса (Backend -> Frontend)
- **Эндпоинт:** `GET /api/progress/:lessonId`
- **Формат ответа:** Объект, где ключами являются `taskId`:

```json
{
  "taskId_1": {
    "latestAttempt": { ... }, // Попытка для задания целиком (если применимо)
    "subTasks": {
      "subTaskId_1": { ... }, // Последняя попытка для подзадачи 1
      "subTaskId_2": { ... }  // Последняя попытка для подзадачи 2
    }
  }
}
```

## 3. Frontend: Восстановление состояния

### Composable `useLessonProgress`
Отвечает за загрузку прогресса при открытии страницы урока:
- Метод `loadProgress(lessonId)` отправляет запрос к `/api/progress/:lessonId`.
- Полученные данные передаются в дочерние компоненты через входной параметр `savedState`.

### Контракт компонентов заданий
Все интерактивные компоненты (`QuizSelect`, `FillInTheBlank`, `DragAndDrop` и др.) принимают входной проп:

```javascript
props: {
  savedState: {
    type: Object,
    default: null
  }
}
```

### Логика восстановления (в хуках `created` или `mounted`):
1. Проверить наличие `savedState`.
2. Если состояние передано, извлечь ответы (из `latestAttempt` или `subTasks`).
3. Заполнить локальную реактивную модель (`userAnswers`, `userSelections` и т.д.).
4. Установить флаг `showResults = true` (блокирует повторный случайный ввод и отображает валидацию/подсветку ошибок).
