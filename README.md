#developer 

## Назначение
Я делаю интерактивный учебник по русскому языку. Он состоит из двух типов уроков:
- **теоретические**: лонгрид с разными механиками заданий,
- **практические**: направлены на изучение конкретного правила русского языка. Практика даётся в виде алгоритма с последовательностью шагов: это граф, дерево решений. 

В будущем в проекте будут психометрические расчёты, с помощью которых мы будем знать сложность каждого задания и уровень успеваемости каждого ученика. 

На основе этих расчетов мы построим адаптивное обучение: в практических заданиях ученику будем давать задания, соответствующие его уровню подготовки. 

Пока в проекте реализован лишь фундамент этой системы: правильная запись данных в базу и сохранение прогресса. 

## Структура папок проекта

Базовый каркас проекта построен на **Nuxt 3** с использованием Vue-экосистемы. Ниже приведено краткое описание основных директорий:

- `/components` — **Vue-компоненты**. Здесь хранятся все переиспользуемые элементы интерфейса и интерактивные задания (`QuizSelect`, `FillInTheBlank`, `DragAndDrop` и т.д.).
- `/composables` — **Переиспользуемая бизнес-логика (Vue Composables)**. Здесь находится, например, скрипт `useLessonProgress.ts`, отвечающий за глобальное состояние прогресса на клиенте.
- `/layouts` — Общие шаблоны (Layouts) страниц (хидер, футер, обертки). Ниже уровня страниц.
- `/lessons` — **Контент уроков**. Сюда сохраняются `.json` файлы с JSON-деревом каждого сгенерированного урока.
- `/pages` — **Роутинг приложения (Nuxt Pages)**. Файловая маршрутизация (например, `pages/lesson/[id].vue` отвечает за отображение нужного урока).
- `/public` и `/assets` — **Статические файлы** (изображения, фавиконки, глобальные стили).
- `/scripts` — **Вспомогательные скрипты**. Локальные тулзы, например, для инициализации базы данных или запуска разовых миграций.
- `/server` — **Бэкенд проекта**. Работает на движке Nitro. Содержит API-роуты (`/server/api`) и конфигурацию базы данных Drizzle (`/server/db`).
- `/utils` — **Утилиты и сервисы**. Функционал, доступный глобально. В частности, `AnalyticsService.js` для отправки попыток и прогресса на бэкенд.
- `/референсы` — **Вспомогательные инструменты и прототипы**. Здесь лежит локальная SPA админ-панель (`admin-panel.html`) для визуального конструирования уроков.

## Архитетура фронтенда
фронтенд построен на **Nuxt.js (Vue 3)** и использует довольно гибкую систему рендеринга на основе JSON-конфигурации (Data-Driven UI).

Вот подробный разбор того, как это работает:

### 1. Роутинг и страница урока

Вся магия происходит в файле `pages/lesson/[id].vue`. Это динамический роут Nuxt.

- **Механизм:** Когда пользователь открывает ссылку вида `/lesson/lesson1`, Nuxt передает `lesson1` как параметр `id`.
- **Загрузка данных:** Внутри компонента есть функция `loadLesson(id)`. Она ищет нужный урок в файле `lessons/index.js` (который служит реестром/манифестом всех уроков).
- **Ленивая загрузка:** Сами данные уроков (JSON-файлы) загружаются "лениво" (dynamic import), только когда они нужны. 

### 2. Рендеринг контента (`SimpleRenderer`)

Если урок обычный (не граф/дерево решений), используется компонент  `SimpleRenderer.vue`.

- **Принцип:** Он получает массив блоков из JSON-файла урока (поле `content`).
- **Диспетчеризация:** Проходит циклом (`v-for`) по этому массиву и для каждого блока вызывает метод `getComponent(node)`.
- **Маппинг:** Поле `type` из JSON (например, `"QuizCheckbox"`, `"Table"`, `"markdown"`) превращается в конкретный Vue-компонент ( `QuizCheckbox.vue`, `Table.vue`, `Markdown.vue`), который и отрисовывается.

### 3. Структура данных (JSON)

Уроки лежат в папке `lessons/`. Например, `lesson1.json`:
- Это массив объектов.
- Каждый объект — это отдельный блок на странице (абзац текста, таблица, квиз).
- У блоков есть `id`, `type`, `content` (текст вопроса, варианты ответов и т.д.) и специфичные для типа поля (например, `correct` для ответов). Подробнее об этом написано ниже в документации в разделе «архитектура хранения данных»

### 4. Особый случай: Деревья решений (Decision Tree)

В `pages/lesson/[id].vue` есть проверка `isDecisionTree`.
- Если это дерево решений (как 'lesson-pol'), загружается другой лейаут (`GraphLayout`) и другой компонент рендеринга — `DecisionTreeLesson.vue`.
- Данные для них берутся из `graph.json` (структура графа) и `graph-task.json` (задания).

### Итог: 
это отличная расширяемая архитектура. Чтобы добавить новый тип задания, нужно просто создать новый Vue-компонент, добавить его в `SimpleRenderer` и использовать новый `type` в JSON-файле урока.


## Архитектура бэкенда

бэкенд полностью интегрирован в фреймворк **Nuxt 3** (использует движок **Nitro**). Это современное решение, где серверная часть ("server routes") живет рядом с фронтендом.

Основные компоненты:

### 1. Серверный движок (Nitro)
- Все файлы в папке `server/api` автоматически становятся API-эндпоинтами.
- Пример: Файл `server/api/attempts.post.ts` обрабатывает POST-запросы по адресу `/api/attempts`.
### 2. База данных (PostgreSQL + Drizzle ORM)

- **PostgreSQL**: Используется как основная база данных (настроена в `drizzle.config.ts`).
- **Drizzle ORM**: Используется для работы с БД. Схема данных описана в `server/db/schema.ts`. Это TypeScript-описание ваших таблиц (например, таблицы `attempts`), которое Drizzle использует для создания SQL-миграций.
### 3. Архитектура обработки запроса (на примере `/api/attempts`)

Когда фронтенд отправляет данные о попытке:
- **Аутентификация**: Сервер проверяет наличие куки `uid` (ID пользователя). Если его нет — возвращает ошибку 401.
- **Валидация**:
    - Проверяются обязательные поля (`taskId`, `answerType`, etc.).
    - Если задача связана с графом (`graphId`), запускается специальная проверка логики графа (`validateGraphNode`).
- **Логика**: Сервер сам определяет, правильный ли ответ (`isCorrect`), и выставляет балл (`score`). Это защищает от подделки результатов на клиенте.
- **Сохранение**: Данные нормализуются и сохраняются в таблицу `attempts` через **Репозиторий** (`attemptRepo.create`). Это слой абстракции, чтобы код API не работал с БД напрямую.

### Итог
Это монолитное приложение (Nuxt), где бэкенд — это набор бессерверных функций (event handlers), которые валидируют данные и пишут их в Postgres через Drizzle.

## Архитектура хранения данных

Этот документ описывает архитектуру хранения данных, API для работы с прогрессом и структуру контента уроков. Предназначен для быстрой погрузки AI-ассистента в контекст проекта.

### 1. База Данных (PostgreSQL + Drizzle ORM)

Основная таблица для хранения прогресса — `attempts`. В ней хранится **каждая попытка** ответа пользователя на конкретное задание или подзадачу. 

#### Схема таблицы `attempts`

| Поле                | Тип         | Описание                                                |
| ------------------- | ----------- | ------------------------------------------------------- |
| `attemptId`         | `uuid`      | PK, генерируется автоматически                          |
| `userId`            | `text`      | ID пользователя (из cookie `uid`)                       |
| `sessionId`         | `uuid`      | ID сессии (из cookie sid)                               |
| `lessonId`          | `text`      | ID урока (например, `lesson1`)                          |
| `taskId`            | `text`      | ID компонента-задания (например, `l1-n4-qchk-o2pn`)     |
| `subTaskId`         | `text`      | ID подзадачи (для составных заданий, nullable)          |
| `taskType`          | `text`      | Тип задания (QuizSelect, FillInTheBlank и т.д.)         |
| `answerType`        | `text`      | Тип ответа (`select`, `input`, `match`, `multi-select`) |
| isCorrect           | `boolean`   | Верно ли решено задание                                 |
| `answerText`        | `text`      | Текстовый ответ пользователя (для input задач)          |
| `selectedOptionId`  | `text`      | ID выбранной опции (для select задач)                   |
| `selectedOptionIds` | `jsonb`     | Массив ID (для multi-select или drag-and-drop)          |
| `createdAt`         | `timestamp` | Время попытки                                           |

**Важно:** Прогресс строится на основе **последней** попытки (`ORDER BY createdAt DESC LIMIT 1`) для каждой пары `taskId` + `subTaskId`.

---

### 2. API и Сохранение Прогресса

#### Сохранение данных (Frontend -> Backend)

Используется `AnalyticsService.logAttempt(payload)`.

- **Endpoint:** `POST /api/attempts`
- **Логика:** Каждое действие проверки (нажатие "Проверить") отправляет новую запись в `attempts`. Не обновляет старые записи, а создает новые (history log).

#### Восстановление прогресса (Backend -> Frontend)

- **Endpoint:** `GET /api/progress/:lessonId`
- **Возвращает:** Объект, где ключи — это `taskId`.

``` json
{
  "taskId_1": {
    "latestAttempt": { ... }, // Попытка для самого компонента (если применимо)
    "subTasks": {
      "subTaskId_1": { ... }, // Последняя попытка для подзадачи 1
      "subTaskId_2": { ... }  // Последняя попытка для подзадачи 2
    }
  }
}

```

### 3. Frontend Архитектура (Vue 3 + Nuxt)

#### Composable: 
`useLessonProgress` Отвечает за загрузку данных при инициализации урока.
- `loadProgress(lessonId)`: Запрашивает данные с API.
- Данные передаются в компоненты через проп `savedState`.

#### Компоненты заданий

Все интерактивные компоненты (QuizSelect, FillInTheBlank и др.) принимают проп:

``` javascript
props: {
  savedState: {
    type: Object,
    default: null
  }
}

```


**Логика восстановления (в** `created` или `mounted`):
1. Проверяем наличие `savedState`.
2. Если есть, извлекаем ответы (из `latestAttempt` или `subTasks`).
3. Заполняем модель данных (`userAnswers`, `userSelections` и т.д.).
4. Если ответы восстановлены, устанавливаем `showResults = true` (блокируем ввод, показываем валидацию).

### 4. Структура JSON Уроков и Специфика Компонентов

Файлы уроков лежат в `/lessons/*.json`.
Корневая структура создается через Admin Panel и выглядит так:
```json
{
  "lesson_id": "lesson1",
  "lesson_version": "v.1.0",
  "topicId": "topic_morphemika",
  "content": [ ...массив узлов... ],
  "schema": "v1"
}
```

Ниже расписано: как выглядит **внутренний JSON шаблон (пропсы)** узла в Admin Panel, а также **как происходит запись в БД (Payload)** для каждого интерактивного компонента.

#### Общие особенности всех узлов контента

- `type`: Тип компонента (строка).
- `id`: Уникальный ID узла.
- `content`: Объект с данными задания, UI-текстами (кнопки, фидбек) и структурой внутри компонента. В целях читаемости JSON этот блок всегда пишется перед глобальными метаданными.
- **Метаданные (на одном уровне с content):** поля `taskVersion` (версия), `skill_id` (скилл), `answer_type` (тип логирования на бэкенд), `blocked` (блокировка UI).
- **Поддержка Markdown:** Большинство текстовых полей внутри `content` (вопросы `question`, `text`, условия задач `tasks`, тексты обратной связи `feedback`, `result_text`) из коробки поддерживают Markdown-рендеринг (`markdown-it`). Это означает, что вы можете использовать `**жирный текст**`, `*курсив*`, а также вставлять HTML-теги для изображений `<img src="/lessons/image.svg" class="lesson-image">` (используя глобальный класс `.lesson-image` для аккуратного форматирования). Единственное ограничение — `options` внутри выпадающего меню `SelectList`.


#### 1. `QuizSelect` (Выбор одного варианта)
Это выбор одного варианта из выпадающего списка

**Шаблон JSON:**
```json
{
  "type": "QuizSelect",
  "id": "l1-n1-qsel-abcd",
  "taskVersion": "v.1.0",
  "skill_id": "",
  "answer_type": "select",
  "blocked": false,
  "content": {
    "question": "Вопрос с единичным выбором",
    "options": [
      { "id": "l1-n1-qsel-abcd-o1", "content": "Вариант 1", "correct": false, "feedback-selected": null, "feedback-not-selected": null },
      { "id": "l1-n1-qsel-abcd-o2", "content": "Вариант 2 (верный)", "correct": true, "feedback-selected": null, "feedback-not-selected": null }
    ],
    "button_text": "Проверить",
    "result_text": "Пояснение к ответу."
  }
}
```

- **Правила записи в БД (Payload):**
  - `taskType`: `"QuizSelect"`
  - `answerType`: `"select"`
  - `subTaskId`: ID конкретного списка (`task.id`).
  - `selectedOptionId`: ID выбранной опции (`option.id`).
  - `isCorrect`: `true`, если выбрана правильная опция (`option.correct === true`).
  - **Счетчики:** `correctOptions` (1), `incorrectOptions` (кол-во опций - 1).
  - **Ответ пользователя:** `selectedCorrectOptions` (1 или 0), `selectedIncorrectOptions` (0 или 1).

#### 2. `QuizCheckbox` (Множественный выбор)

**Шаблон JSON:**
```json
{
  "type": "QuizCheckbox",
  "id": "l1-n2-qchk-abcd",
  "taskVersion": "v.1.0",
  "skill_id": "",
  "answer_type": "multi-select",
  "blocked": false,
  "content": {
    "question": "Вопрос с множественным выбором",
    "options": [
      { "id": "l1-n2-qchk-abcd-o1", "content": "Вариант 1 (верный)", "correct": true, "feedback-selected": null, "feedback-not-selected": null },
      { "id": "l1-n2-qchk-abcd-o2", "content": "Вариант 2", "correct": false, "feedback-selected": null, "feedback-not-selected": null }
    ],
    "button_text": "Проверить",
    "result_text": "Пояснение к ответам."
  }
}
```

- **Особенности:** Запись идет на уровне всего задания (без `subTasks`).
- **Правила записи (Payload):**
  - `taskType`: `"QuizCheckbox"`
  - `answerType`: `"multi-select"`
  - `subTaskId`: `null`.
  - `selectedOptionIds`: Массив ID выбранных опций (массив строк).
  - `isCorrect`: `true`, если выбраны **все** правильные и **ни одной** неправильной опции (строгое совпадение).
  - **Счетчики:** `correctOptions` (общее число правильных опций в задании), `incorrectOptions` (общее число неправильных).
  - **Ответ пользователя:** `selectedCorrectOptions` (совпадения правильных), `selectedIncorrectOptions` (выбранные неправильные).

#### 3. `QuizSet` (Набор мини-заданий / радио-кнопок)
**Шаблон JSON:**
```json
{
  "type": "QuizSet",
  "id": "l1-n3-qset-abcd",
  "taskVersion": "v.1.0",
  "skill_id": "",
  "answer_type": "select",
  "blocked": false,
  "content": {
    "question": "Серия мини-заданий",
    "options": [
      { "id": "l1-n3-qset-abcd-opt1", "content": "Вариант A" },
      { "id": "l1-n3-qset-abcd-opt2", "content": "Вариант B" }
    ],
    "tasks": [
      { "id": "l1-n3-qset-abcd-t1", "content": "Текст задания 1", "correct_option": "l1-n3-qset-abcd-opt1", "feedback-correct": "Верно!", "feedback-incorrect": "Неверно!" }
    ],
    "button_text": "Проверить",
    "button_next_text": "Следующее задание",
    "result_text": "Общий фидбек."
  }
}
```

- **Особенности:** В блоке может быть несколько вопросов с вариантами ответа.
- **Правила записи (Payload):**
  - `taskType`: `"QuizSet"`
  - `answerType`: `"select"`
  - `subTaskId`: ID вопроса (`task.id`).
  - `selectedOptionId`: ID выбранного ответа.
  - `isCorrect`: `true`, если `selectedOptionId` совпадает с `task.correct_option`.
  - **Счетчики:** `correctOptions` (1), `incorrectOptions` (кол-во опций - 1).

#### 4. `FillInTheBlank` (Ввод текста в пропуски (инпуты))
**Шаблон JSON:**
```json
{
  "type": "FillInTheBlank",
  "id": "l1-n4-fibl-abcd",
  "taskVersion": "v.1.0",
  "skill_id": "",
  "answer_type": "input",
  "blocked": false,
  "content": {
    "question": "Заполните пропуски",
    "tasks": [
      { 
        "id": "l1-n4-fibl-abcd-t1", 
        "text": "Я сижу за стол___", 
        "correctAnswers": ["ом"], 
        "answerType": "single", 
        "minWidth": null, 
        "feedback-correct": null, 
        "feedback-incorrect": null 
      }
    ],
    "button_text": "Проверить",
    "result_text": "Молодцы!"
  }
}
```

- **Особенности:** В каждом пропуске пользователь вводит текст. 
  - Поле `answerType` управляет поведением инпута: `single` (однострочное поле), `single-box` (увеличенное поле ввода).
  - В `correctAnswers` можно передавать массивы синонимов, используя синтаксис внутри строк в админке `Слово 1, [син1 | син2], Слово 3`. При выгрузке в JSON получается `["Слово 1", ["син1", "син2"], "Слово 3"]`. Если пользователь ввел любой из синонимов подмассива, ответ засчитывается как верный для конкретного инпута.
- **Правила записи (Payload):**
  - `taskType`: `"FillInTheBlank"`
  - `answerType`: `"input"`
  - `subTaskId`: ID пропуска (`task.id`).
  - `answerText`: Введенный пользователем текст. Если полей ввода несколько в рамках одной подзадачи, их значения склеиваются через точко с запятой и пробел (`; `).
  - `isCorrect`: `true`, если введенный текст совпадает (без учета регистра и лишних пробелов) хотя бы с одним из вариантов `correctAnswers`.

             "correctAnswers": [""], 
             "placeholder": "впишите ответ",

             "feedback-incorrect": null 
          }

    },

#### 12. `DecisionTree` / `Graph` (Интерактивный граф-дерево)

Архитектура дерева решений (графа) отличается от обычных компонентов и разделена на два файла контента: 
1. **Файл самого графа (`graph.json`)** — описывает схему самого дерева, узлы (вопросы/шаги), связи (переходы по опциям) и результаты.
2. **Файл заданий для графа (`graph-task.json`)** — массив заданий, привязанных к конкретному графу, которые ученик решает, проходя по дереву и вписывая финальный ответ.

**Шаблон JSON Графа (`graph.json`):**
```json
{
  "graphId": "graph_pol_v1",
  "title": "Правописание пол- и полу-",
  "layout": "spine",
  "start_node": "q1",
  "ruleId": "rule_pol",
  "topicId": "topic_morphemika",
  "nodes": [
    {
      "id": "q1",
      "type": "question",
      "answer_type": "select",
      "text": "Это приставка ПОЛУ-?",
      "skill_id": "pristavka",
      "options": [
        { "id": "q1_op_yes", "label": "Да", "next": "r_slitno_polu" },
        { "id": "q1_op_no", "label": "Нет", "next": "q2" }
      ]
    },
    {
      "id": "r_slitno_polu",
      "type": "result",
      "label": "слитно (полу-)",
      "text": "ПОЛУ- всегда пишется слитно."
    }
  ]
}
```

**Шаблон JSON Задания для графа (`graph-task.json`):**
```json
{
  "id": "t1",
  "type": "graph",
  "graphId": "graph_pol_v1",
  "ruleId": "rule_pol",
  "topicId": "topic_morphemika",
  "taskVersion": "v.1.0",
  "answer_type": "input",
  "input_id": "t1_input",
  "content": {
    "word": "пол…яблока",
    "correct_answer": "пол-яблока",
    "correct_result": "r_defis",
    "correct_path": [
      { "id": "q1", "skill_id": "pristavka", "option_id": "q1_op_no" },
      { "id": "q2", "skill_id": null, "option_id": "q2_op_yes" }
    ]
  }
}
```

**Особенности работы с БД для Графа (Payload):**
В отличие от обычных компонент уроков, граф отправляет аналитику в БД **двумя разными способами** по ходу взаимодействия пользователя с интерфейсом:

1. **Шаг внутри дерева (`ActiveTree.vue`)**
   При клике на любую кнопку (опцию) внутри активного дерева решений (например, ответ "Да" на вопрос узла), отправляется отдельная попытка:
   - `taskType`: `"DecisionTree"`
   - `answerType`: `"select"`
   - `subTaskId`: ID узла-вопроса в графе (напр. `"q1"`).
   - `taskId`: ID самого задания (`task.id`, напр. `"t1"`).
   - `selectedOptionId`: ID выбранной опции (`"q1_op_no"`).
   - `isCorrect`: `true`, если этот шаг совпадает с `correct_path` из задания.
   - Обогащается метаданными графа (`graphId`, `topicId`, `ruleId`, `skillId` узла).

2. **Ввод и проверка финального ответа слова (`DecisionTreeLesson.vue`)**
   Когда ученик доходит до узла с результатом (Result) и вводит текстовый ответ в поле в левой колонке:
   - `taskType`: `"DecisionTreeInput"`
   - `answerType`: `"input"`
   - `subTaskId`: ID инпута (поле `input_id` из задания, напр. `"t1_input"`).
   - `taskId`: ID задания (`"t1"`).
   - `answerText`: Введенный пользователем текст.
   - `isCorrect`: `true`, если точное текстовое совпадение с `correct_answer`.
   - `responseMs`: Время (в миллисекундах), затраченное на решение **всей** задачи с момента её появления.

## Конструктор уроков (Admin Panel)

Инструмент `референсы/admin-panel.html` представляет собой Single Page Application (SPA), написанное на чистом HTML/CSS/JS, работающее полностью локально в браузере. Его главная цель — упростить и стандартизировать сборку JSON-файлов уроков.

### Архитектура интерфейса
Панель разделена на 3 колонки:
1. **Левая колонка (Контент урока):** Сборка структуры урока (дерево узлов). Здесь можно добавлять новые узлы (markdown, Table, интерактивные компоненты), изменять их порядок, дублировать или удалять.
2. **Центральная колонка (Редактор узла):** Графический интерфейс для заполнения пропсов выделенного слева узла (ввод текста, правильных ответов, добавление опций/колонок).
3. **Правая колонка (Урок):** Live-превью сгенерированного JSON-объекта всего урока, настройка метаданных (`lesson_id`, `topicId`), система сохранения черновиков (в `localStorage`), валидация JSON и экспорт в готовый `.json` файл.

### Ключевые функции
- Автогенерация ID для узлов (`l{lesson}-n{nodeIndex}-{typeAbbr}-{salt}`) и их дочерних элементов (`-o1`, `-t1`).
- Поддержка связей: если у `DragAndDrop` удаляется группа, на которую ссылается карточка, админка предупредит об этом.
- Встроенный валидатор, который проверяет целостность данных перед экспортом (например, что есть ровно один правильный ответ в `QuizSelect`, что `correctAnswers` является массивом и т.д.).


## Ключевые требования к разработке новых фич

1. **Idempotency:** Перезагрузка страницы не должна терять прогресс.
2. **Partial State:** Если задание решено частично (неверно), прогресс все равно должен восстанавливаться, показывая пользователю его ошибки (режим `showResults`).
3. **Immutability:** Старые записи в `attempts` не редактируются. Всегда создаются новые.
